# PRODUCT — RED 视频下载助手 v1.0

## 1. 背景与目标
已有小红书用户反馈：开发者工具内搜索 MP4 地址门槛高，网页变化导致地址难找；有用户期待下载视频时没有水印。已有网页端开源工具在产品负责人实际测试的样本上下载出无水印视频。**此为有限人工观察，不保证插件环境或所有样本一致。**

目标：用户在 Chrome 桌面版浏览具体的小红书视频笔记时，点击浏览器工具栏扩展图标，即可查看当前视频信息并主动保存当前视频文件，无需开发者工具、复制链接、安装 Python/Docker/本地服务。

## 2. 用户与平台
- 用户：不懂开发者工具的普通桌面 Chrome 用户。
- 运行：Chrome Manifest V3 扩展，工具栏 `action` Popup。
- 名称：`RED 视频下载助手`（非官方产品；不可暗示小红书官方授权）。
- 免费：v1.0 单视频下载免费、无登录、无会员。

## 3. 确定范围
1. 点插件图标打开右上角 Popup；**不会自动下载**。
2. 判断当前活动标签页是否打开具体的小红书**视频作品**（不是首页、搜索页、图文页）。
3. 识别成功时展示视频标题、短提示、视频文件大小（可取得则显示，无法确定则显示“大小未知”，不阻塞下载）。
4. 主要操作为红色圆形按钮：下载图标 + “下载” + 文件大小；用户点击后启动**单个当前视频**的下载。
5. 每次主动下载使用 Chrome 原生另存为对话框（`chrome.downloads.download({ saveAs: true })`），用户可选择文件夹并修改文件名；使用过滤非法字符的标题生成建议文件名。
6. 依据浏览器反馈显示：检测中、可下载、下载中、完成、失败；明确区分非视频页面、视频解析失败和用户取消保存。
7. 使用可验证的现有资源获取流程，**不额外进行裁剪、遮盖、转码、去水印处理**；实际下载结果的水印状态以测试为准。

## 4. 明确不做
- 不支持图文图片保存（网页版已有右键保存能力）。
- 不支持多作品/账号批量下载、自动遍历、后台抓取。
- 不提供账号系统、付费、云解析、第三方上传、推广广告。
- 不要求用户安装独立运行环境。
- 不实现规避访问控制、验证码或频率限制。

## 5. 行为边界
- 页面无可下载视频时提示“此页面没有可下载的内容～”。
- 明确在视频作品页但资源无法解析时提示“暂时无法识别这个视频”，可指引刷新、重试。
- “取消保存”不是下载失败；不能提前宣布下载成功。
- 文件大小无法确认时仍允许用户下载（前提是存在实际可用的媒体资源）。
- 如果 Popup 关闭，后台下载应尽量不中断；重新打开时状态须与浏览器真实下载状态保持一致，具体实现待 P0/P1 验证。

## 6. 质量、安全及版权
- 不收集/外传用户登录凭证、浏览记录或视频文件。
- 遵循最小权限原则；权限请求、外部连接和依赖都需有用途说明。
- 下载仅面向用户有权保存的素材；尊重内容创作者权利与平台规则。
- 两个参考项目许可证必须核实；如直接改编和发布其 GPL 代码，应履行相应许可证义务。

## 7. 成功定义
在同一批授权视频样本上，能安装、正确识别状态、获取可用下载资源、弹出另存为窗口、成功保存可播放文件，并如实反馈失败/取消。具体测试清单见 `ACCEPTANCE.md`。
