# TASKS — 双工具相同的任务基线

各阶段只能在上一阶段有明确结论后启动；执行工具分别维护自己的状态/进展，不修改共享任务定义。

## P0 技术审查（第一轮）
输出独立 `TECHNICAL.md`，记录两个参考仓库固定 commit，关键函数/调用链、MV3 兼容性、依赖及许可、风险、最小实验。**禁止在此阶段开发完整扩展。**

## P1 最小可运行验证
建立 MV3 最小扩展：当前授权视频页识别 → 取得可用视频地址 → 点击后原生 saveAs 下载单文件。允许最简占位 UI，但不允许模拟下载冒充成功。

## P2 Popup UI
实现 UI-SPEC 标题、红色圆形按钮、可得的文件大小、无视频/解析失败等状态；无额外业务功能。

## P3 下载状态与异常
处理真实 Chrome downloads 完成/中断事件，Popup 关闭/重开、另存为取消、文件名清理、错误展示。

## P4 测试与交付
运行 ACCEPTANCE 的统一测试，修正问题，补充最简安装 README 与权限/许可证声明，保留开发与验证证据。

## 不纳入本轮
图文图片、跨作品批量、账号采集、收费、后台服务、绕过平台访问限制。
